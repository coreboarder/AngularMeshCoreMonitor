The most critical shifts and new features in Angular 22 that will shape your project's architecture include:

1. The Signals Revolution Graduating to Stable
While previous versions introduced the core mechanics, v22 brings the highly anticipated ecosystem features out of experimental status.  
Medium

Stable Signal Forms (@angular/forms/signals): The legacy, RxJS-heavy FormControl and FormGroup patterns are no longer the exclusive option. Signal Forms are now production-ready. They offer fine-grained, deeply typed reactivity out of the box, drastically reducing the template boilerplate and the performance overhead associated with deeply nested forms.  
Medium
+ 1

The Resource API (httpResource and rxResource): Say goodbye to manually handling HttpClient subscriptions or mapping observables with toSignal().  
Reddit

httpResource() is optimized around the Fetch API, natively mapping network requests into clean, responsive signal states.

rxResource() handles scenarios where your underlying data source is an existing, complex RxJS Observable stream, bridging the gap perfectly.

2. Default Architectural Changes
Angular 22 enforces a significantly lighter, faster baseline for newly initialized apps.

ChangeDetectionStrategy.OnPush by Default: New components generated by the CLI implicitly use OnPush. The framework only checks components exactly when their specific inputs or local signals change, which is a massive leap forward for rendering efficiency and pushes apps closer to dropping zone.js entirely.

Vitest as the Standard Test Runner: The slow, resource-heavy Karma/Jasmine pipeline is completely replaced. New projects default to Vitest, which shares the same build pipeline configuration and executes unit tests up to 10x faster. A migration tool (migrate-karma-to-vitest) handles legacy codebases.  
Telerik.com

3. High-Performance SSR & Routing
If your project requires high SEO performance, lightning-fast initial page loads, or complex UI rendering, these platform optimizations change the game:

Incremental Hydration by Default: Combined with @defer blocks, Angular 22 loads and hydrates server-side rendered application code incrementally as components scroll into the user's view. It reuses data fetched on the server without triggering double API calls, completely removing the user-facing "flicker".  
Telerik.com

Decoupled Browser URLs: The router received brilliant ergonomic updates. The new browserUrl parameter on RouterLink allows you to maintain a clean aesthetic URL in the address bar while routing to a different internal, parameter-heavy layout under the hood (e.g., displaying /settings while the router actually points to /account/advanced-preferences).  
Telerik.com

Automatic Parameter Inheritance: Child routes now cleanly inherit parent parameters by default, ending the old headache of writing custom inject chains just to retrieve an ID up the routing tree.  
Telerik.com

injectAsync(): You can now lazy-load heavy services on-demand while still cleanly instantiating them through Angular's core dependency injection ecosystem.  
Telerik.com

import { component, signal, httpResource } from '@angular/core';

@Component({
  selector: 'app-mesh-monitor',
  template: `
    @if (meshData.isLoading()) { <p>Connecting to mesh...</p> }
    @if (meshData.error()) { <p>Error: {{ meshData.error() }}</p> }
    
    @for (node of meshData.value(); track node.id) {
      <node-card [data]="node" />
    }
  `
})
export class MeshMonitorComponent {
  // A reactive parameter driving the network request
  currentFrequency = signal('915MHz'); 

  // Completely handles loading, error, status, and value signals automatically
  meshData = httpResource(() => `/api/mesh/nodes?freq=${this.currentFrequency()}`, {
    pollingInterval: 2000 // Native polling out-of-box
  });
}

The "Floral" Way vs. The "Framework Flex" Way
The Floral Way (Don't do this)
You use standard CSS transitions, or you update a rotation property using traditional Angular [{ngModel}] or string interpolation inside a legacy zone-based app. The framework spends massive CPU cycles dirty-checking the entire component tree 60 times a second just to spin boxes.

The Framework Flex Way (Do this)
Make each node a 3D Flip Card or a Compass-Rotating Dial where the rotation angle or face-flip is bound to a fine-grained Signal.

For example, when a MeshCore device reports a change in directional signal strength, or when a packet hops through it, you reactively update its transform properties.

// Inside your ultra-lean Node Component
readonly rotationAngle = computed(() => {
  // Directly derive the rotation angle from live MeshCore telemetry signals
  return (this.nodeTelemetry().signalStrength * 3.6) + 'deg';
});
